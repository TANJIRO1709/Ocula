# Deploying Ocula

You need a GitHub account and a free [Render](https://render.com) account. Push this folder to a GitHub repository first:

```bash
cd ocula
git init && git add . && git commit -m "Ocula"
git branch -M main
git remote add origin https://github.com/<you>/ocula.git
git push -u origin main
```

## Option A — everything on Render (one-click Blueprint)

1. Render Dashboard → **New → Blueprint** → select your `ocula` repo. Render reads `render.yaml` and proposes:
   `ocula-db` (Postgres), `ocula-engine` (FastAPI), `ocula-api` (Node gateway), `ocula-web` (Next.js).
2. It asks for the values marked `sync: false`:
   * `ADMIN_PASSWORD` — your staff dashboard password (**set this**).
   * `LLM_API_KEY`, `LLM_BASE_URL`, `TWILIO_*` — optional, leave empty for now.
3. Click **Apply**. First build takes ~5–10 minutes. The services find each other automatically:
   the gateway gets the engine's and frontend's public hostnames, and the frontend gets the gateway's.
4. Open `https://ocula-web….onrender.com` → Start eye check. Staff dashboard: `/dashboard` with `admin@ocula.app` and your password.

**Check the wiring:** open `https://ocula-api….onrender.com/readyz` — it should show `"engine": {"status": "ok"}`.
If it shows the engine as down, open **ocula-api → Environment** and set `ENGINE_URL` to the engine's URL
(e.g. `https://ocula-engine-abcd.onrender.com`), then redeploy. Likewise, if the browser shows CORS errors,
set `CORS_ORIGINS` on ocula-api to your frontend URL.

## Option B — backend on Render, frontend on Vercel

1. Deploy the Blueprint as above but delete the `ocula-web` block from `render.yaml` first
   (and remove the `FRONTEND_HOST` entry under `ocula-api`).
2. On [Vercel](https://vercel.com): **Add New → Project** → import the repo → **Root Directory: `frontend`**.
   Add environment variable `NEXT_PUBLIC_API_URL = https://ocula-api….onrender.com/api/v1` → Deploy.
3. On Render → **ocula-api → Environment**: set
   `CORS_ORIGINS = https://your-app.vercel.app` and `PUBLIC_BASE_URL = https://your-app.vercel.app` → save (redeploys).

## Free-tier notes (important for a live demo)

* Free Render web services **sleep after 15 minutes idle** and take **about a minute** to wake.
  Ocula softens this: the frontend pings `/readyz` as soon as the home page opens (waking gateway + engine while
  the customer reads the consent screen), the gateway keeps the engine warm while it's awake, and engine calls
  retry while it wakes up. **Before a demo, open the site ~2 minutes early.**
* Free services can't receive private-network traffic, so services call each other over public HTTPS,
  protected by the shared `ENGINE_API_KEY` (generated automatically by the Blueprint).
* The free Render Postgres **expires 30 days after creation** — upgrade it or recreate it after the hackathon.
* 750 free instance-hours per month are shared across free services; sleeping services don't use hours.

## Optional integrations

| Feature | Where | Variables |
|---|---|---|
| LLM (better free-speech understanding, any language, warmer explanations) | `ocula-engine` | `LLM_PROVIDER` = `openai` / `anthropic` / `openai_compatible`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_BASE_URL` |
| Real missed-call line + SMS | `ocula-api` | `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`. In Twilio, set the number's voice webhook to `POST https://ocula-api….onrender.com/api/v1/telephony/missed-call?lang=hi`. Webhooks are verified with `X-Twilio-Signature`. |
| Offline face model | `frontend` | Run `node scripts/fetch-model.mjs` and set `NEXT_PUBLIC_FACE_MODEL_URL=/models/face_landmarker.task` |

Without these, everything still works: rule-based multilingual understanding, template explanations,
SMS/calls logged to the gateway console, and the `/phone` simulator for the missed-call demo.

## Production checklist

* `SECRET_KEY` (auto-generated by the Blueprint) and a strong `ADMIN_PASSWORD`.
* Verify catalog product names and set prices in **Dashboard → Catalog**.
* Have Hindi / Odia texts reviewed by native speakers.
* Health: `/healthz` (gateway + DB), `/readyz` (gateway + engine), `/metrics` (Prometheus) on the gateway; `/healthz` on the engine.
